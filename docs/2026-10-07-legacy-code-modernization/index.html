4つのプログラム

swserv（サーバ）、xsw（クライアント）、monitor（監視ツール）、unvedit（宇宙ファイルのエディタ）

プロジェクト

25年で、何が壊れていたか

古い C++ の書き方

当時は通った書き方が、今のコンパイラではエラーになる。廃止されたヘッダ <iostream.h>、型を省略した宣言（暗黙の int）、文字列リテラルを const なしで受ける代入など

当時の CPU 専用のビルド設定

25年前の Intel CPU 向けの指定（-march=i586 など）が残っていて、今のマシンではビルドできない

64bit 対応

32bit 前提のコードが全体に散らばっていた。ポインタを int に入れる処理や、long のサイズを決め打ちした処理は、64bit では値が欠けて壊れる。通信やファイル形式に影響しないかも調べた

CPU で変わる型の扱い

char 型に負の値を入れられるかは CPU で違う。x86 では動いた「-1 を入れる」処理が、arm64 では壊れる

消えたライブラリ

サウンド（YIFF / EsounD）とジョイスティック（libjsw）

対象外 OS の残骸

AIX・HP-UX・Solaris・Windows 向けの分岐とビルド用ファイル

プロジェクト

移植後の状態

対応 OS

Linux / FreeBSD に加え、macOS（Apple Silicon）にも対応。XQuartz は不要

ビルド

4つのプログラムすべてが gcc 14 の -Wall で警告 0（抑止オプションなし）

互換性

挙動・ネットワークプロトコル・データファイル形式は変更なし

グラフィック

macOS では X11 の代わりに SDL2 で描く。X11 の部品を SDL2 で再現する層を新しく作った

サウンド

SDL2_mixer で効果音と背景音楽（MIDI）を再生。macOS で動作を確認

ジョイスティック

SDL2 で読み取り（実機では未確認）

テスト

スモークテストが主要な動作を PASS / FAIL で自動判定

成功の要因 ／ STEP 1

SKILLS は作業の手順書が2つ

build-linux

ビルドとエラー対応の手順

  • scripts/build.sh でビルドし、ログのエラーを種類別に集計する
  • 同じパターンのエラーはまとめて直す
  • エラー数と警告数の推移を報告する
  • 64bit・プロトコル・ファイル形式に関わる判断は PORTING_NOTES.md に追記する

run-headless

画面なしで起動を確かめる手順

開発環境は macOS 上のコンテナで、画面がない。Claude Code がそこを調べ、この確認方法を自分で用意した

  • まず scripts/smoke.sh で主要な動作を自動判定する
  • Xvfb 上でサーバとクライアントを起動し、画面を撮って確認する
  • 内部の値は gdb で読む。クラッシュしたらバックトレースを取る

繰り返す作業のやり方を書いておくと、Claude Code が必要なときに読んで使う

成功の要因 ／ ルール

特に効いた4つのルール

RULE 1 ／ 変えないもの

ゲームの挙動・プロトコル・データファイル形式は変えない。最小限の修正で動かす

理由　頼んでいない改善に手を広げず、修正が小さく収まる。迷ったときの判断基準にもなる

RULE 2 ／ ごまかさない

-fpermissive・-w・警告の一括抑止でごまかさない。警告を黙らせるだけのキャストはしない

理由　ビルドを通すだけの近道を塞ぐ。根本原因を直すので、後から実行時に壊れる手戻りを防げる

RULE 3 ／ コミット

修正は小さな単位でコミットし、メッセージに「現代の環境で何が壊れていたか」を書く

理由　原因を言葉にしてから直すことになる。問題が出ても、どの修正かをすぐ特定できる

RULE 4 ／ 記録

移植中に判明した非自明な事項は docs/PORTING_NOTES.md に追記する

理由　一度調べたことを次の作業でも使える。人間が後から経緯を追える

成功の要因 ／ 道具

確かめる道具も、AI が自分で作った

scripts/build.sh

ビルドしてログを残し、最後にエラーと警告の数を表示する

scripts/headless.sh

画面のない環境（Xvfb）で起動し、スクリーンショットの取得やキー入力の送信を行う

scripts/smoke.sh

4つのプログラムを起動し、ログイン、操作、保存、音の出力などを PASS / FAIL で自動判定する。macOS 用の smoke-macos.sh も追加

これらのスクリプトは AI が自分で考えて作り、作業が進むにつれて勝手に育てていった
